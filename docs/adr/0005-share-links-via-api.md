# ADR-0005: קישורי שיתוף חיצוניים — רק דרך ה-API

- **סטטוס:** התקבל
- **תאריך:** 2026-10-11
- **מקורות:** 08_workplan_v2 §2 (הכרעה 6), 06_security (SEC-26–29), 04_architecture (החלטה פתוחה 15), review_consistency (סתירה 5)

## הקשר

04 הציע להחליף טוקן שיתוף ב-JWT `share_viewer` ל-15 דקות שניגש ישירות ל-DB עם RLS. זה מתנגש בדרישת ביטול תוך 60 שניות (SH-02), מרחיב את משטח ה-RLS לישות לא מאומתת, ומקשה על סימן מים, הסתרת טבלת כותרת ו-rate limit.

## החלטה

- הצופה החיצוני ניגש **רק ל-endpoints read-only ייעודיים ב-API** (`/v1/share/{token}/...`). אין JWT ל-DB, אין role `share_viewer`.
- טוקן אקראי **256 ביט** (base64url); ב-DB נשמר **SHA-256** בלבד. בכל בקשה ה-API מאמת: קיים, לא בוטל, לא פג.
- הקישור **נעול לפרויקט ולגרסה**. קריאה בלבד, בלי גישה לקובץ המקור. **הורדת PDF כבויה** כברירת מחדל.
- תוקף: ברירת מחדל **14 יום**, מקסימום **90**. ביטול מיידי בידי editor/admin (SEC-07), אוטומטי במחיקת פרויקט או offboarding.
- **טבלת הכותרת מוסתרת** כברירת מחדל; **סימן מים** דינמי על אריחים.
- כותרות: `X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`. rate limit לפי IP ולפי טוקן; כל צפייה נרשמת ב-audit.

## השלכות

- (+) ביטול מיידי (הבדיקה בכל בקשה), מקום אחד לאכיפה, אין חשיפת DB.
- (−) עומס על ה-API לכל אריח בצפייה חיצונית — מתון: signed URLs קצרים לאריחים שה-API מנפיק אחרי אימות הטוקן.
- 05_ux מתעדכן: תוקף 14/30/90, אין הורדה כברירת מחדל, רק editor/admin יוצרים קישור.
